# 橘線觀測站 v1.1

中和新蘆線個人車隊追蹤工具。手機與筆電使用同一個後端，共用 SQLite 資料庫；不需要 npm install，不使用付費 AI API。

## 先知道目前能做什麼

- 28 組固定編組：401/402 至 455/456。補登單一車號，固定搭檔同步為編組推定；保留實際目擊車號。
- 全車隊格狀總覽、搜尋與狀態篩選、近期上線、當日曾上線、多日未見清單。
- 車組日曆、歷史時間軸、照片、車次／支線、人工工程註記與歷史、未見區段與恢復上線。
- 以台灣營運日計算，預設 04:00 切日，可在設定調整。這是使用設定，並非已串接官方營運日定義。
- 檢修級別重疊時並列；離峰短時間未見不推估一、二級檢修。
- 明日上線歷史頻率、可能性等級與估計區間；完整觀測不足時顯示資料不足。
- JSON 完整備份與合併還原、CSV 匯出、個人存取金鑰、深淺色模式。
- 公開列車到站站名已內建，伺服器會嘗試每60秒取得。網路失敗保留最後資料，顯示取得與來源更新時間。
- 自訂車號來源可設定欄位映射與車號代碼表。輔助來源支援 JSON 擷取、快取、檢視。

**v1.1 已接入北捷公開動態資訊頁的車組資料，可自動累積車組上線紀錄，無需先取得北捷會員 API。** 來源：https://web.metro.taipei/pages2026/WebCorner/O 。每輪擷取可見列車元素的車組編號、目的地及頁面更新時間；時間超過10分鐘或格式無法解析時，暫停寫入新紀錄。此來源為網站頁面解析，非具有穩定格式承諾的官方API。正式會員接口仍可額外設定作為更完整來源。套件不含假資料或預填工程名單。

公開動態頁尚未解析精確所在站與車次。公開頁顯示的車組順序用作首端車號，並在備註明確標示非親眼目擊。不同頁面區段重複出現的相同編組會去重。範圍外編組在資料來源頁列示，不會自動擴充你指定的401–456車隊。頁面未顯示某車組不能當成停駛或完整觀測日。

車站時刻表、捷運路網、捷運線型、營運路線等資料可透過 sources.json 設定來源後取得及檢視；本版尚未將時刻表自動轉成尖離峰模型、用線型繪製地圖，或以站序自動推導方向。方向目前依目擊目的地顯示，車次只推支線。

## Windows 筆電啟動

1. 安裝 Python 3.10 以上，建議 3.12；官方下載：https://www.python.org/downloads/ 。安裝時勾選 Add Python to PATH。
2. 將 ZIP 完整解壓縮到一般資料夾，例如 `D:\orange-line-tracker`。不要直接從 ZIP 內執行。
3. 雙擊 `start-windows.bat`，保留命令視窗開啟。
4. 第一次啟動會建立 `data` 資料夾。用記事本開啟 `data/access-key.txt`，複製金鑰。
5. 瀏覽器打開 http://localhost:8787 ，貼上金鑰進入。
6. 右上角「補登目擊」即可開始。不需要事先設定 API。

若雙擊失敗，在該資料夾的終端機執行：

```powershell
py -3 server.py
```

Mac / Linux：

```sh
python3 server.py
```

沒有第三方 Python 套件，無須 pip install。`package.json` 只提供可選的 npm 指令，並非 Node 後端。

## Android 手機與筆電同步

1. 手機和筆電連同一個可信任 Wi-Fi。
2. 筆電命令提示字元執行 `ipconfig`，找到目前 Wi-Fi 的 IPv4 位址，例如 `192.168.1.20`。
3. 手機瀏覽器打開 `http://192.168.1.20:8787`；輸入同一份存取金鑰。
4. Windows 防火牆若詢問，僅允許私人網路。前端每30秒更新，也可按「更新」。

紀錄存於同一台伺服器，不是各裝置 localStorage；瀏覽器只保留本次分頁的存取金鑰。照片也同步。手機可將網站加入主畫面，但本版不具離線寫入與背景推播功能。

手機行動網路無法直接連線筆電的私人 IP。若要外出使用，可把服務放在持續運作的私人主機，並透過 VPN 或 HTTPS 反向代理存取。不要直接把本程式的明文 HTTP 埠公開到網際網路。

## 全天候持續蒐集

關閉瀏覽器不會停止伺服器擷取；關閉伺服器視窗、筆電睡眠或關機則會停止。要在筆電關閉後仍蒐集，需另外部署到常開主機、NAS 或 VPS。本 ZIP 提供 Dockerfile 與 compose.yaml，沒有代你租用或部署外部主機。

已安裝 Docker 的主機：

```sh
docker compose up -d --build
docker compose exec tracker cat /app/data/access-key.txt
```

第二行會顯示你的金鑰，只在自己的裝置查看，不要貼到公開場所。資料使用持久化 volume；勿使用 `docker compose down -v`，該參數會刪除資料。

設定 sources.json 時，依 compose.yaml 註解加入唯讀掛載。憑證透過環境變數設定，勿寫進前端。若 API 不是 Bearer 認證，需依官方實際規格修改對接器，不能假設通用範例即為北捷格式。

## 推估如何運作

### 事實與推估分開

- 最近10分鐘有載客目擊：近期確認上線，仍非「此刻必然在線」。有效時間可調。
- 當營運日曾有載客目擊：今日曾上線，收車不抹掉當日紀錄。
- 試車與機廠目擊：保留時間軸，不當成載客上線。
- 車次401–420：依使用者規則標記迴龍／南勢角；430–449：蘆洲／南勢角。其他車次不亂猜。車次不等於實體車號。

### 未見與檢修

未見日數為距最後載客目擊的營運日差，不是確認停駛天數。沒有紀錄的車組顯示「尚無紀錄」。

預設第3日起考慮檢修，需最後目擊後、今天之前的所有中間營運日都經確認完整觀測。資料不足時仍顯示未見日數，但不判級。單次 API 成功不代表整日完整，本版不會自動填造完整性。

在「設定與備份 → 完整觀測日管理」確認已結束營運日的資料；只有確實涵蓋全車隊與營運時段才能標完整。不完整的資料即使很多，也不應標完整。

候選時間依使用者提供的參考表，並非本程式核實的北捷正式檢修制度：

| 距最後目擊 | 候選（另須達門檻與完整觀測） |
|---|---|
| 1–3日 | 三級 |
| 3–7日 | 四級；第3日與三級並列 |
| 8–13日 | 原因未定 |
| 14日以上 | 五級／大修可能性 |

工程需要人工來源註記。新的載客證據會自動顯示「工程起始後曾恢復上線」，但不把施工狀態改成已完工；可以再追加完工紀錄，舊紀錄保留。

### 明日上線頻率

近30個已結束營運日中，只取標記完整的營運日。預設至少14日，才顯示 `(有上線日數+1)/(完整觀測日數+2)` 的百分比。≥67%為較可能，≤33%為較不可能，其餘普通。顯示 Wilson 95%歷史比例區間。

這是未校準的基礎歷史頻率估計，不是北捷排班模型；未納入里程、實際檢修週期、排班或時刻表，不宣稱可以準確預告某日出車。近期上線、今日上線及明日預估三者分開顯示。

## 備份與搬家

- 網頁可匯出 JSON（含照片、工程歷史與觀測日）及 CSV。
- 匯入採新增合併，已存在的同一目擊跳過；不覆蓋目前設定及既有完整觀測標記。
- 匯入上限20MB。照片每張3MB以下；資料很多時，先停止程式，再整個複製 `data` 資料夾。
- `data/tracker.sqlite3` 是資料庫，`data/access-key.txt` 是個人金鑰；更換金鑰後需重啟服務。
- 刪除目擊保留稽核紀錄；網頁 JSON 備份不含稽核表，完整保留需備份 SQLite。

## 測試與限制

執行：

```sh
python -m unittest discover -s tests -v
node --check static/app.js
```

交付前完成36項自動測試，包含編組連動、跨午夜、資料缺口、檢修重疊、非載客排除、機率樣本、工程恢復、身分驗證、備份與非法輸入。JS語法檢查通過。官方公開到站資料及動態頁曾實際取得，動態頁解析實測取得21組範圍內車組。

本次環境的瀏覽器預覽轉送服務不可用，未完成真實瀏覽器與實機手機視覺驗證；Windows雙擊啟動與Docker部署也未在對應平台實測。正式北捷車號接口尚未取得，因此尚未做該接口端到端測試。

## 專案結構

- `server.py`：HTTP、SQLite、權限、備份、資料擷取。
- `core.py`：營運日、車組、檢修與上線頻率。
- `adapter.py`：明確欄位映射與車號代碼對照。
- `metro_web.py`：北捷公開動態頁車組解析、時間驗證與範圍篩選。
- `static/`：繁體中文手機／電腦介面。
- `sources.example.json`：車號及輔助來源設定範例。
- `API申請與對接.md`：官方資料用途、來源、接口契約與申請準備。
- `tests/`：自動驗證。

## 從v1.0更新

先停止舊服務，把原本 `data` 資料夾備份並複製到新版專案根目錄，再啟動新版。不要同時啟動兩個服務使用同一資料庫。新版保留原有金鑰、目擊、工程與設定；資料庫欄位相容。
